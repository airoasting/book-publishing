# 공통 규칙

## 리뷰어 띄우기

SKILL.md '리뷰어 격리'를 따른다. Agent 도구가 있으면 리뷰어마다 서브에이전트를 띄우고 아래 프롬프트를 쓴다.

```
너는 {역할}이다. {역할 설명}
읽을 것: {원고 경로}, {책 설정 경로}의 기본 정보·페르소나·저자 자료·목차·장 작성 가이드·작성 스타일
(사실 검증가만 추가: {01_citations.json 경로}, {01_research-notes.md 경로})
원고가 길면 {draft/{책}/_read/{원고ID}/pNN.md} 조각을 순서대로 읽는다.
아래 루브릭으로만 지적한다. 칭찬은 쓰지 않는다. 점수는 쓰지 않는다.
지적 형식: (공통 지적 형식 붙여 넣기)
루브릭: (해당 리뷰어 루브릭 붙여 넣기)
결과는 지적 목록만 돌려준다.
```

원고가 길면 먼저 `BOOK split {원고ID}`로 읽기용 조각을 만든다. 서브에이전트 결과를 받아 리뷰 파일에 그대로 옮긴다. 결과를 요약하거나 고치지 않는다.

## 지적 형식

모든 지적은 이 형식이다. 줄 맨 앞의 `[🔴]`, `[🟡]`, `[🟢]`(또는 `[필수]`, `[권장]`, `[참고]`)를 `BOOK score`가 센다. 앞에 `-`, `1.`, `>`, `**`가 붙어도 된다.

- **지적은 표나 코드 블록으로 쓰지 않는다.** 지적 줄이 아닌 곳(표, 코드 블록, 설명 문장)에 심각도 기호가 있으면 채점을 거부한다
- **위치에는 부나 장 이름을 쓴다** (`[제2부 제5장 둘째 절]`, `[프롤로그]`, `[부록 A]`). 수정 단계가 그 부를 실제로 고쳤는지 확인하는 데 쓴다. 책 전체에 걸친 지적은 `[전체]`. 🔴 지적에 부나 장 이름이 없으면 채점을 거부한다
- 지적이 하나도 없으면 `지적 없음` 한 줄을 쓴다
- 합평은 모든 지적이 `## 평가자 N` 섹션 안에 있어야 하고, 평가자마다 지적이나 `지적 없음`이 있어야 한다
- **지적 섹션에는 지적 줄과 그 하위 항목(`- 원문:`, `- 문제점:`, `- 수정 제안:`, `- 근거:`)만 쓴다.** 설명, 총평, 소감은 `## 총평` 섹션에 쓴다 (마케터의 '한 줄 소개 후보'는 `## 한 줄 소개 후보` 섹션). 지적 섹션의 자유 문장, `#`·`###` 헤딩, 코드 블록, 점수 섹션 뒤에 붙인 지적은 형식에서 벗어난 지적일 수 있으므로 채점을 거부한다. 거부되면 리뷰 파일을 손으로 고치지 않는다. Claude Code에서는 오류 메시지를 붙여 같은 리뷰어를 다시 띄우고, 격리가 없는 앱에서는 같은 역할로 리뷰를 처음부터 다시 쓴다. 사용자에게는 "리뷰 형식을 맞춰 다시 받는 중"이라고 한 줄만 알린다

리뷰 파일 구조:

```
# 04. 비평가 리뷰

## 총평
(선택. 자유롭게 쓴다)

## 지적 사항
[🔴] [제2부 제5장] - 제목
- 문제점: …
```

```
[🔴] [제2부 제5장 둘째 절] - 출처 없는 가격 수치
- 원문: "월 19.99달러로…" (길면 첫 30자 + …)
- 문제점: 무엇이 왜 잘못인가
- 수정 제안: 어떻게 고치는가
```

| 심각도 | 기준 | 반영 의무 |
|--------|------|-----------|
| 🔴 필수 | 출판 불가. 사실 오류, 출처 없는 수치, 근거 없는 체험담, 논리 모순, 목차 누락, 검증 규칙 위반, 맞춤법 오류, 비문 | 100% 반영 |
| 🟡 권장 | 고치면 확실히 나아짐. 표현, 흐름, 예시 보강 | 판단 후 반영 |
| 🟢 참고 | 취향, 대안 제안 | 무시 가능 |

## 점수와 지적 ID

리뷰어는 점수를 쓰지 않는다. 리뷰 파일을 다 쓰면 `BOOK score {리뷰ID}`를 실행한다. 스크립트가 하는 일:

- 지적마다 ID를 붙인다: `[🔴] [R04-03] [위치] - 제목`. 합평은 평가자 번호가 들어간다 (`R08-2-01`은 합평 1라운드 평가자 2의 첫 지적)
- SKILL.md '점수 기준'대로 점수 표와 🔴 지적 ID 목록을 파일 끝에 붙이고 완료 마커를 단다
- `_state.json`에 지적 목록(지적이 가리킨 부 포함)과, 리뷰한 원고의 해시를 남긴다. 리뷰 뒤에 원고가 바뀌면 `status`가 다시 리뷰하라고 알리고, 같은 리뷰를 다시 채점하는 것은 거부한다 (`BOOK reset`으로 되돌린 뒤 새로 리뷰)

다시 채점해도 ID는 같은 순서로 다시 매겨진다. 다시 채점해서 🔴 지적이 줄거나 위치나 내용이 바뀌면 `--reason "이유"`가 필요하고, 기록에 남는다 (채점 전 리뷰 원문은 `_backup/`에 남는다).

## 수정 단계 (05, 07, 09, 11, 15)

`BOOK status`가 수정 단계를 가리키면 출력의 `입력`(기준 원고, 리뷰 목록)을 쓴다.

1. 리뷰의 지적을 부별로 묶는다
2. 지적이 있는 부만 `{수정본ID}_pNN.md`로 새로 쓴다. 기준 원고의 해당 부를 복사해 지적된 곳만 고친다. **지적 없는 문장은 건드리지 않는다** (저자 목소리를 지키고 비용을 줄이기 위해서다)
3. 조각마다 `BOOK complete {수정본ID}_pNN`
4. `_changelog.md`에 `## {수정본ID}` 섹션을 쓴다 (형식은 SKILL.md '변경 로그'). 각 행의 항목 칸에 지적 ID를 적는다. 🔴 지적 ID는 하나도 빠짐없이, 반영 칸 ✅로
5. `BOOK merge {수정본ID}`. 스크립트가 다음을 확인하고 하나라도 어긋나면 거부한다
   - 🔴 지적 ID가 모두 반영 칸이 `✅`, `✅ 반영`, `✅ 완료` 중 하나인 행에 있는가, 리뷰에 없는 ID를 쓰지 않았는가 (사유 칸의 ID는 세지 않는다)
   - 🔴 지적이 가리킨 부마다 고쳐 쓴 조각이 있고, 그 조각이 기준 원고와 실제로 다른가 (공백만 바꾼 것은 고친 것이 아니다)
   - 조각마다 부 헤딩이 하나이고 목차의 부와 이름이 맞는가 (병합은 위치가 아니라 부 이름으로 맞춘다)
   - 병합본에 규칙 위반 🔴이 없는가 (`_verify-{수정본ID}.md` 보고서). 있으면 해당 조각을 고쳐 다시 병합한다

수정 원칙:

- 책 설정의 페르소나로 고친다
- 지적 없는 문장을 다듬지 않는다. 리뷰가 거듭될수록 문장이 밋밋해지는 것을 막기 위해서다
- 리뷰어가 일화나 수치를 "추가하라"고 해도 SKILL.md '사실 무결성'을 넘지 않는다
- 리뷰어끼리 상충하면 사실 검증가 > 교정자 > 편집자 > 나머지 순으로 따르고, 변경 로그 사유에 적는다

## 단계 사이 안내

리뷰 구간은 작업 시간이 가장 긴 구간이다(리뷰 7번과 수정 5번). 사용자가 혼자 기다리지 않게, 리뷰나 수정 하나를 끝낼 때마다 `status`의 `진행:` 줄을 써서 이렇게 알린다.

```
[4단계 중 3단계(리뷰) · 리뷰와 수정 12번 중 3번째 · 전체의 약 53%] 독자 리뷰 완료: 🔴 2건, 🟡 5건 (점수 6/10).
다음: 지적받은 2개 부를 고칩니다. 여기서 멈춰도 "이어서 해줘"라고 하면 이 지점부터 이어집니다.
```

`auto_continue`가 true면 멈추지 않고 다음 단계로 간다. false면 리뷰 하나와 그 수정까지 한 번에 하고 멈춘다. `chunk_unit`이 `two_parts`(두 부씩)면 리뷰와 수정을 두 묶음씩 하고 멈춘다. Claude 앱과 ChatGPT에서는 멈추지 않는 설정이어도 묶음 하나를 마칠 때마다 작업 묶음을 내보낸다 (SKILL.md '이어 가기').

# 합평 (5단계, 6단계)

5인이 같은 원고를 각자 읽고 독립적으로 지적한다. 서브에이전트 5개를 한 메시지에서 동시에 띄운다. 리뷰 파일은 다음 구조이고, `BOOK score`는 `## 평가자 N: 이름` 섹션이 정확히 5개일 때만 점수를 낸다.

```
# 08. 합평 리뷰 (1라운드)
격리: 서브에이전트 5개 (또는 '없음 (같은 컨텍스트에서 작성, 신뢰도 낮음)')

## 평가자 1: 사실 검증가
(지적 목록)

## 평가자 2: 구조 검증가
...
## 평가자 5: 서식 검증가
...
```

### 평가자 1: 사실 검증가

`01_citations.json`과 `01_research-notes.md`를 대조한다.

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 사실 | 출처와 다른 수치·날짜·명칭 | 표현이 모호 |
| 출처 | 수치·인용에 `[[cite_…]]` 없음, 없는 ID | Tier 3 단독 인용 |
| 일관성 | 같은 수치가 장마다 다름 | 단위 표기 비통일 |
| 체험담 | 화자 성격이 실제 저자인데 저자 자료에 없는 1인칭 체험이나 실명 일화 | |
| 고지 | 화자 성격이 가상 화자인데 프롤로그에 재구성 사례 고지가 없음 | |
| 기준 연도 | 책 설정 기준 연도와 다른 예시 연도 (사실 정보 제외) | |

### 평가자 2: 구조 검증가

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 목차 | 책 설정 목차 항목 누락 | 하위 절 누락 |
| 분량 | 한 부가 다른 부의 2배 이상 또는 절반 이하 (계획된 차이 제외) | 장 사이 편차가 큼 |
| 연결 | 목차에 적힌 브릿지 누락, 다음 부와 연결 끊김 | 브릿지가 약함 |
| 장 구성 | 책 설정 '장 작성 가이드' 요소 누락 | 요소 순서 비일관 |
| 인물 | 앞에서 소개한 인물이 예고 없이 사라짐 | 등장 빈도 불균형 |

### 평가자 3: 논리 검증가

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 근거 | 근거 없는 단정 | 근거가 약한 추론 |
| 비약 | 전제와 결론 사이 단계 누락 | 연결어 부적절 |
| 중복 | 같은 메시지가 장마다 반복 | 장 안 표현 중복 |
| 모순 | 앞 장과 뒤 장의 주장이 충돌 | 뉘앙스 차이 |

### 평가자 4: 독자 검증가

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 용어 | 미설명 용어로 진행 불가 | 설명 부족 |
| 따라 하기 | 절차가 끊겨 실행 불가 | 한 단계 모호 |
| 흥미 | 도입부에서 덮고 싶음 | 중간 흥미 약화 |
| 목소리 | 책 설정 '말투'가 깨져 다른 사람이 쓴 것처럼 읽힘 | 개성 있는 표현이 수정 과정에서 밋밋해짐 |

### 평가자 5: 서식 검증가

책 설정 '검증 규칙'과 SKILL.md '원고 마크업 규약'으로 본다. 기계 검사(`verify.py`)가 잡는 항목은 반복하지 말고, 사람 눈이 필요한 것만 본다.

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 마크업 | 규약에 없는 표기로 변환이 깨질 곳 | 헤딩 레벨 비일관 |
| 그림 | 그림 자리 캡션이 내용과 맞지 않음 | 캡션 형식 비통일 |
| 표 | 표가 깨지거나 열 수가 맞지 않음 | 표 헤더 표기 비통일 |
| 박스 | 장 작성 가이드가 요구한 핵심 정리 박스 누락 | 박스 형식 비통일 |

## 5단계: 합평 1라운드 (`08_ensemble-review-1`)

입력 `07_draft-v3`. 끝나면 `BOOK score 08_ensemble-review-1`, 이어서 수정 단계 `09_draft-v4`.

## 6단계: 합평 2라운드 (`10_ensemble-review-2`)

입력 `09_draft-v4`. 같은 5인, 같은 루브릭이다. 끝나면 `BOOK score 10_ensemble-review-2`. 판정은 스크립트가 한다.

- 통과 (🔴 0건, 평균 9점 이상): 수정 단계 `11_draft-final`로 간다. 남은 🟡을 판단해 반영한다
- 미통과, 2라운드: `BOOK next-round`. 스크립트가 09와 10을 백업하고 3라운드를 연다. `BOOK status`가 3라운드 수정의 입력(백업된 원고와 리뷰)을 알려준다. 09를 다시 만들고 10을 다시 리뷰한다
- 미통과, 3라운드: 더 돌리지 않는다. `11_draft-final` 변경 로그에 미통과 사유와 남은 🔴 처리 내용을 적고 진행한다. 🔴은 이때도 모두 반영해야 병합된다

# 외부 리뷰

## 7단계: 편집자 (`12_review-editor`)

역할: 20년 차 출판 편집자. "독자가 이 책을 끝까지 읽는가"가 기준이다. `## 총평` 섹션에 총평 한 문단을 쓰고 (점수 없이), 지적은 `## 지적 사항` 섹션에 쓴다.

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 구성 | 부와 부 사이 흐름이 끊김 | 흐름은 무난하나 힘이 약함 |
| 서사 | 도입 훅이 없음, 인물 일관성 붕괴 | 인물이 평면적 |
| 톤 | 장마다 화자가 달라짐 | 장별 톤 강도 편차 |
| 분량 | 한 부가 전체의 30% 초과 또는 5% 미만 | 장 사이 편차 |
| 독자 경험 | 중반에 덮을 만한 지점 | 쉬어 갈 곳 부족 |
| 차별점 | 같은 주제의 기존 책과 다른 점이 안 보임 | 차별점이 약함 |
| 완성도 | 목차에 있는 부록·참고문헌 누락 | 부록 형식 비통일 |

## 8단계: 마케터와 교정자 (13, 14)

두 리뷰는 `11_draft-final`을 각자 읽는다. 서로의 결과를 보지 않는다. 동시에 띄워도 된다.

### 마케터 (`13_review-marketer`, 참고용)

서점 MD에게 책을 한 줄로 소개해야 하는 마케터다. 본문 수정에는 반영하지 않고, `/publish`의 메타데이터 입력으로만 쓴다. `## 한 줄 소개 후보` 섹션에 후보 3개를 쓰고, 지적은 `## 지적 사항` 섹션에 쓴다.

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 타깃 | 누구를 위한 책인지 한 줄로 말할 수 없음 | 타깃이 둘 이상으로 흐림 |
| 제목 | 제목만으로 가치가 전달되지 않음 | 제목이 평이 |
| 프롤로그 | 첫 3쪽에 훅이 없음 | 훅이 약함 |
| 목차 | 목차만 보고 흥미가 안 생김 | 일부 장 제목이 평이 |
| 시의성 | 1년 안에 낡을 정보가 중심 | 일부 사례의 유통기한이 짧음 |

### 교정자 (`14_review-proofreader`)

20년 차 교정교열 전문가. 감정 없이 사실만 지적한다. 위치는 부·장·절까지 정확히 쓴다.

| 항목 | 🔴 | 🟡 |
|------|----|----|
| 맞춤법 | 표준국어대사전 기준 명백한 오류 | 띄어쓰기 비통일 |
| 비문 | 주어와 서술어 호응이 깨짐 | 길어서 뜻이 흐림 |
| 용어 | 책 설정 '용어 통일'·금지 용어 위반 | 같은 개념을 다른 말로 씀 |
| 문체 | 책 설정 어미와 다른 서술 종결 | 문장 길이 편차 |
| 부호 | 책 설정 검증 규칙의 부호 위반 | 따옴표 종류 비통일 |
| 숫자 | 같은 수치가 장마다 다름 | 단위 표기 비통일 |
| 참조 | "3장에서 본" 같은 내부 참조가 실제 위치와 다름 | 장 번호 표기 비통일 |
