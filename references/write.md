# 구조 설계와 초안

> 책쓰기 2단계. SKILL.md의 지시로 로드되는 실행 문서다. `BOOK`은 `python3 "$SKILL_DIR/scripts/book.py"`다.

## 시작

1. `BOOK status`를 실행한다. 출력이 가리키는 곳부터 한다 (구조 설계, 목차 승인 대기, 조각 N 작성, 톤 승인 대기, 병합 중 하나)
2. 책 설정에서 기본 정보, 페르소나, 저자 자료, 목차, 장 작성 가이드, 작성 스타일을 읽는다
3. `01_research-notes.md`의 장별 "본문에 쓸 수 있는 수치" 목록을 확인한다

## 작업 설정 (이 책에서 처음 한 번만 묻는다)

`draft/{책}/_state.json`의 `config`가 비어 있으면 한 번 묻는다 (`AskUserQuestion` 같은 선택지 도구가 있으면 쓰고, 없으면 대화로 묻는다). 이미 있으면 다시 묻지 않는다.

- 질문: "한 번에 얼마나 진행할까요? (초안과 리뷰 모두에 적용됩니다)"
- 선택지
  1. **부 하나씩 (권장)**: 부 하나를 쓰고 멈춘다. "이어서 써줘"라고 하면 다음 부를 쓴다. 대화가 길어져 품질이 떨어질 위험이 가장 낮다
  2. **두 부씩**: 두 부를 쓰고 멈춘다. 리뷰 구간에서는 리뷰와 그 수정을 두 묶음씩 하고 멈춘다
  3. **끝까지**: 멈추지 않고 마지막 부까지 쓴다. 분량이 큰 책은 중간에 대화가 끊길 수 있다. Claude Code에서는 끊겨도 쓴 데까지 남고, Claude 앱과 ChatGPT에서는 부를 하나 쓸 때마다 만들어 드리는 작업 묶음 ZIP을 내려받아 두면 그 지점부터 이어진다
- 저장: 1번 `BOOK config chunk_unit=part auto_continue=false`, 2번 `BOOK config chunk_unit=two_parts auto_continue=false`, 3번 `BOOK config chunk_unit=part auto_continue=true`

사람 확인 지점(목차 승인, 톤 승인)은 이 설정과 무관하게 멈춘다.

## 1단계: 구조 설계 → `02_outline.md`

- 목차의 부와 장마다 핵심 메시지 한 줄, 다룰 내용, 리서치에서 가져올 사실(출처 ID), 목표 분량을 표로 정한다
- 분량 배분: 목표 분량을 부와 장에 나눈다. 한 부가 전체의 30%를 넘거나 5%에 못 미치지 않게 한다
- 부 사이 연결: 목차에 적힌 브릿지 문장을 어디서 어떻게 받을지 정한다
- 등장인물이 있는 책이면 인물별 등장 위치를 정한다. 인물과 일화는 SKILL.md '사실 무결성'을 따른다
- 장마다 그림 자리(무엇을 보여줄지)를 한 줄로 정한다
- 다 쓰면 `BOOK complete 02_outline`

### 사람 확인 1: 목차 승인

`02_outline.md`를 그대로 보여주지 말고 요약해서 보여준다.

```
[4단계 중 2단계(집필)] 목차 설계를 마쳤습니다. 확인해 주세요.

| 부 | 장 | 핵심 메시지 | 분량 |
|----|----|-------------|------|
| ... |

이대로 초안을 쓸까요? 바꿀 곳이 있으면 말씀해 주세요.
```

승인되면 `BOOK approve outline`. 수정 요청이면 `02_outline.md`를 고치고 다시 보여준다 (마커는 그대로 둔다).

## 2단계: 초안 → `03_draft-v1_pNN.md` → `03_draft-v1.md`

### 조각 규칙

- 조각 하나 = 목차의 부(`###`) 하나. 번호는 목차 순서다 (p01 = 첫 부, 보통 프롤로그)
- 조각의 첫 줄은 그 부의 헤딩이다: `# 프롤로그: 제목`, `# 제1부: 제목`. `BOOK complete`가 이 줄을 목차와 대조한다
- 조각을 끝까지 쓰면 `BOOK complete 03_draft-v1_pNN`
- 대화가 끊겼다가 돌아오면 `BOOK status`가 마커 없는 조각을 알려준다. 그 파일 끝에 이어 쓴다. 덮어쓰지 않는다

### 사람 확인 2: 톤 승인

장이 있는 첫 부(보통 p02, 제1부)를 완료하면 그 부의 첫 2쪽 분량(약 1,000~1,200자)을 그대로 보여주고 묻는다: "이 목소리로 끝까지 써도 될까요?" 프롤로그는 본문보다 사적인 톤이라 기준으로 삼지 않는다. 승인되면 `BOOK approve tone`. 수정 요청이면 그 조각을 고쳐 다시 보여준다. 승인 전에는 다음 부로 넘어가지 않는다 (스크립트가 막는다).

### 작성 원칙

- SKILL.md '작성 원칙', '사실 무결성', '원고 마크업 규약'을 따른다
- 책 설정의 페르소나와 작성 스타일을 처음부터 끝까지 유지한다. 어미, 부호, 불릿은 책 설정 '검증 규칙'이 정한 대로 쓴다
- 수치는 리서치 노트의 "본문에 쓸 수 있는 수치"에서만 가져오고 같은 문장에 `[[cite_…]]`를 붙인다. 설명을 위해 지어낸 예시 수치는 문장 끝에 `[[예시]]`를 붙인다
- 화자 성격(실제 저자, 가상 화자, 조직 화자)에 따른 체험담·일화 규칙은 SKILL.md '사실 무결성'을 따른다. 실명(성, 이름, 직함)은 쓰지 않는다
- 장마다 책 설정 '장 작성 가이드'의 요소를 모두 넣는다
- 그림이 필요한 곳에 `[그림 N: 캡션]`을 한 줄로 넣는다. 번호는 책 전체에서 1부터 이어진다
- 부 끝에는 목차의 브릿지 문장을 `## N부를 마치며` 아래 문단으로 쓴다 (검증 규칙의 브릿지 문구가 다르면 그 문구를 쓴다)

### 한 번에 쓰는 범위

| 설정 | 한 번의 요청에서 |
|------|------------------|
| `part`, `auto_continue=false` | 다음 조각 1개를 쓰고 멈춘다 |
| `two_parts`, `auto_continue=false` | 다음 조각 2개를 쓰고 멈춘다 |
| `part`, `auto_continue=true` | 남은 조각을 모두 쓰고 병합까지 한다 |

멈출 때 안내: `[4단계 중 2단계(집필) · 부 {전체}개 중 {완료}개 완료] 제N부 작성 완료. "이어서 써줘"라고 하면 다음 부를 씁니다.`

### 병합

모든 조각이 완료되면 `BOOK merge 03_draft-v1`. 스크립트가 조각 마커를 지우고 부 이름 순서대로 합친 뒤 규칙 검사를 돌린다. 🔴이 있으면 `_verify-03_draft-v1.md`의 줄 번호를 보고 해당 조각을 고쳐 다시 병합한다. 분량 미달 🔴은 어느 부가 모자란지 `BOOK split 03_draft-v1`로 확인해 보충한다.

### 쪽수 실측 (LibreOffice가 있을 때)

쪽당 글자 수는 그림과 표의 양에 따라 500~800자로 달라진다. 목표가 쪽수라면 초안 단계에서 한 번 재 둔다.

```bash
python3 "$SKILL_DIR/scripts/build_docx.py" "draft/{책}/03_draft-v1.md" --out "draft/{책}/_measure/draft.docx" --no-gate --allow-missing-images --pdf
```

`_measure/build-report.md`의 실측 쪽수가 목표와 10% 넘게 차이 나면 사용자에게 알리고, 책 설정의 목표 글자 수를 실측 비율로 고칠지 묻는다. 고치면 `BOOK accept-toc`.

완료 안내: `[4단계 중 2단계(집필) 완료] 초안 완료 (N자, 실측 약 M쪽, 규칙 점수 X/10). 다음: 리뷰`
