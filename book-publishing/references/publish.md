# 검증, 사실 확인, Word 변환, 메타데이터

> 책쓰기 4단계. SKILL.md의 지시로 로드되는 실행 문서다. `BOOK`은 `python3 "$SKILL_DIR/scripts/book.py"`다.

입력은 `draft/{책}/15_manuscript.md`, 출력 폴더는 `output/{책}/`다. 검사를 통과하고 사용자가 사실 확인을 마쳐야 Word로 변환한다.

## 0. 준비

```bash
python3 "$SKILL_DIR/scripts/book.py" status      # 출판 단계인지 확인
python3 "$SKILL_DIR/scripts/book.py" doctor      # python-docx, matplotlib 확인
```

모듈이 없으면 사용자에게 설치를 요청한다: `pip install -r "$SKILL_DIR/scripts/requirements.txt"`

## 1단계: 규칙 검사

```bash
python3 "$SKILL_DIR/scripts/verify.py" "draft/{책}/15_manuscript.md" --report "output/{책}/verify-report.md"
```

| 종료 코드 | 뜻 | 할 일 |
|-----------|----|-------|
| 0 | 통과 (🔴 0, 9점 이상) | 1.1로 |
| 1 | 🔴 있음 | 보고서의 줄 번호로 `15_manuscript.md`를 직접 고치고 `_changelog.md`의 `## publish-fix` 섹션에 기록한 뒤 다시 검사 |
| 3 | 🔴은 없지만 9점 미만 (보고서 판정 '보류') | 🟡 목록을 쉬운 말로 바꿔 보여주고 ('em dash'는 '긴 줄표', '어미 혼용'은 '~다와 ~니다가 섞임', '불릿 부호'는 '목록 기호') "고치고 갈까요, 이대로 갈까요?"를 묻는다. 고치면 다시 검사한다. 이대로 가면 `BOOK approve low-score --note "사유"`로 사용자 결정을 기록한다. 기준 점수를 낮춰 다시 돌리지 않는다 |

검사 항목 (책 설정 '검증 규칙'에서 기준을 읽는다): em dash, 짝 없는 `**`, 알 수 없는 주석, 완료 마커, 수평선, 어미 혼용(인용·코드·표 제외), 분량, 목차 일치(부와 장), 부 브릿지, 금지 용어, 금지 영어 표현, 불릿 부호, 그림 번호, 장별 그림, 출처 태그(없는 ID, Tier 3 단독, 출처 없는 수치), 알 수 없는 규칙 키.

### 1.1 그림 (사실 확인 전에 만든다)

그림 속 수치도 사실 확인 대상이므로, 그림을 먼저 만들고 사실 확인 표에 함께 올린다. 원고의 `[그림 N]`마다 그림 파일이 있어야 `status`가 사실 확인으로 넘어간다.

```bash
python3 "$SKILL_DIR/scripts/book.py" figures 15_manuscript
```

목록의 그림마다 `output/{책}/figures.py`에 한 줄씩 만든다. `fk`(그림 도구)는 실행할 때 미리 준비되므로 import나 스킬 경로를 적지 않는다 (대화창이 바뀌어 스킬 위치가 달라져도 그대로 돈다). 글꼴, 색, 크기, 파일명은 도구가 고정한다.

```python
fk.flow(1, ["자료 올리기", "질문하기", "노트로 저장"])            # 단계 흐름
fk.compare(2, "사용 전", ["2시간 읽기"], "사용 후", ["5분 요약"])  # 두 열 비교
fk.bars(3, ["무료", "Plus"], [50, 300], unit="개")                 # 수치 비교 (출처 있는 수치만)
fk.timeline(4, [("1주차", "개인 사용"), ("2주차", "팀 공유")])     # 시간 순서
fk.cards(5, [("소스", "올린 자료"), ("노트", "저장한 답")])         # 개념 카드
```

다섯 도구로 표현이 안 되는 그림만 matplotlib으로 직접 그리고 반드시 `fk.save(fig, N)`으로 저장한다. 저장할 때 그림 속 글자와 수치가 `images/figdata.json`에 기록되어 사실 확인 표와 검사기(실명, 금지 용어, 쓰면 안 되는 것)에 들어간다. 그림에 넣는 수치도 출처가 있는 것만 쓴다.

```bash
python3 "$SKILL_DIR/scripts/figure_kit.py" run "output/{책}/figures.py"
```

그림은 `output/{책}/images/figNN.png`로 저장된다.

목표 쪽수가 있고 LibreOffice가 있으면 그림을 만든 뒤 시험 변환으로 쪽수를 한 번 재고, 목표와 크게 다르면 사실 확인 전에 사용자와 분량을 정한다 (사실 확인 뒤에 보충하면 확인을 다시 받아야 한다). 그림 폴더를 꼭 지정한다:

```bash
python3 "$SKILL_DIR/scripts/build_docx.py" draft/{책}/15_manuscript.md --out output/{책}/_measure/final.docx --images output/{책}/images --no-gate --pdf
```
시험 변환은 새면 안 되는 표현을 경고(🟡)로만 남긴다. 출판 변환에서는 같은 표현이 실패(🔴)다.

### 1.2 사람 확인 3: 출판 전 사실 확인

AI가 쓴 책의 사실 책임은 저자에게 있다. 변환 전에 다음을 보여주고 확인받는다. 저자가 직접 열어 볼 수 있게 링크를 꼭 붙인다.

`BOOK facts`로 `output/{책}/fact-check.md`를 만든다. 표는 위험한 것부터 정렬되어 있다 (⚠️ 출처 기록과 다른 수치, 블로그·SNS 출처, 금액과 통계). 맨 앞의 안내 문장("15~30분쯤 걸립니다…")을 그대로 전한다.

1. 규칙 검사 결과 한 줄: `규칙 점수 X/10 (🔴 0, 🟡 N)`
2. 사실 확인 표 상위 20행: 행, 위치, 문장, 수치, 출처, 종류(사내·공식·언론·블로그), 출처에 기록된 내용, 링크. 저자가 본문 수치와 출처 기록을 나란히 비교할 수 있다
3. 표 아래의 그림 속 글자와 수치(그림마다 한 줄, 그림 이미지도 함께 보여 준다. 코드는 보여 주지 않는다), 실명일 수 있는 표현(위험한 순서, 같은 표현은 한 줄로 묶여 있다), 쓰면 안 되는 것, 지어낸 예시 수치 목록. 표가 길면 채팅에는 위험한 항목만 두고 `fact-check.md`를 내려받게 한다
4. 화자 성격별 확인: 실제 저자면 1인칭 체험담 위치와 근거가 된 저자 자료 항목, 가상 화자면 프롤로그의 재구성 사례 고지 문장, 조직 화자면 인물 일화가 없는지
5. 목소리 확인: 중간 부의 한 쪽을 그대로 보여주고, 톤 승인 때의 목소리가 리뷰를 거치며 유지됐는지 묻는다
6. 출판 설정의 'AI 제작 고지' 문구 ('없음'이면 출판사·플랫폼 정책을 확인했는지 묻는다)와 '배포 표기' 문구 (사내 배포 책이면 표지와 쪽 위에 찍힐 말을 그대로 보여 준다)

사실 확인 표는 승인 직전에 `BOOK facts`로 만든 것이어야 한다. 표를 만든 뒤 원고, 그림, 출처, 설정이 바뀌면 `approve facts`가 거부하므로 표를 다시 만들어 보여 준다.

"이대로 출판본을 만들까요?"에 승인을 받으면 `BOOK approve facts`. 고칠 곳이 있으면 `15_manuscript.md`를 고치고 1단계부터 다시 한다. 승인은 원고, 책 설정, 근거 자료(출처 파일, 그림, 사내 자료)에 묶여 있어 어느 하나가 바뀌면 자동으로 무효가 된다.

## 2단계: Word 문서

### 2.1 변환

```bash
python3 "$SKILL_DIR/scripts/build_docx.py" "draft/{책}/15_manuscript.md" --out "output/{책}/final.docx" --pdf
```

- 게이트: `status`, `approve`와 같은 판정(`publish_gate`)을 쓴다. 모든 단계 완료, 책 설정 변경 없음, 병합 뒤 수정 기록, 지금 원고를 다시 검사한 결과(🔴 0), 낮은 점수 승인, 사실 확인 승인을 확인한다. 출력 위치(작업 폴더 밖, 다운로드 폴더)와 상관없이 같다
- 서식은 책 설정 '출판 설정'에서 읽는다. 표지(제목, 부제, 필명, 발행 연월, AI 제작 고지), 차례, 머리글, 쪽 번호, 출처 목록을 만든다
- 변환이 끝나면 docx를 다시 열어 검사하고 `output/{책}/build-report.md`를 쓴다: 마크다운·주석·태그 잔존, em dash, 부 헤딩 수, 그림 누락, 출처 ID, 작성자 속성
- `--pdf`: LibreOffice가 있으면 `final.pdf`를 만들고 실제 쪽수를 재서 목표 분량(쪽)과 비교한다. `pdftotext`도 있으면 각 제목의 실제 쪽을 찾아 차례에 쪽 번호를 넣고 다시 렌더링한다. 실측 쪽수가 목표에서 벗어났다는 🟡이 있으면 사용자에게 알리고, 보충할지 이대로 갈지 묻는다
- 게이트는 사실 확인 승인(`approve facts`)과, 9점 미만이면 낮은 점수 승인(`approve low-score`)까지 확인한다
- 종료 코드 1이면 보고서의 🔴을 고치고 다시 변환한다. 그림이 없다는 🔴이면 1.1을 다시 한다
- 차례: Word로 열 때 '필드 업데이트'를 허용하면 쪽 번호가 붙은 차례가 된다. 갱신하지 않아도(PDF 변환 등) 제목 목록은 들어 있다
- **LibreOffice가 없는 환경(ChatGPT 등)**: `final.pdf`와 실측 쪽수가 나오지 않는다. 사용자에게 이렇게 안내한다: "final.docx를 내려받아 Word(또는 한컴오피스, Google 문서)로 여세요. '필드 업데이트'를 허용해 차례 쪽 번호를 채운 뒤 'PDF로 저장'하면 배포용 PDF가 됩니다. 그때 마지막 쪽 번호가 실제 쪽수입니다." 실제 쪽수가 목표와 10% 넘게 다르면 알려 달라고 하고, 보충할지 정한다

## 3단계: 출판 메타데이터 → `output/{책}/metadata.md`

사내 배포 책(출판 설정 '배포 표기'가 있음)은 서점 등록 항목 대신 사내 배포 안내(배포 대상, 배포 경로, 문의처는 사용자에게 받은 것만)를 쓴다. `status`는 metadata.md도 원고와 같은 기준으로 검사해, 금지 용어나 엄격 모드의 실명이 있으면 완료로 넘기지 않는다.

입력: `15_manuscript.md`, `13_review-marketer.md`(1차 입력), 책 설정.

| 마케터 리뷰 | 메타데이터 |
|-------------|-----------|
| 한 줄 소개 후보 | 도서 설명문 첫 문장 |
| 타깃 평가 | 검색 키워드 후보 |
| 제목 평가 | 부제, 띠지 카피 |
| 시의성 평가 | 출간 시기 제안 |

작성 항목:

- 도서 분류: KDC, BISAC 코드 후보와 근거
- 도서 설명문: 훅 → 가치 → 독자가 얻는 것 → 행동 유도 (내용 요약이 아니라 판매 문구)
- 검색 키워드 7~10개
- 가격대 제안: 같은 분야 도서를 웹에서 찾아 비교한 범위와 근거. 찾지 못했으면 "비교 자료 없음"이라고 쓴다. 판매량이나 순위를 지어내지 않는다
- 플랫폼별 등록 체크리스트: 교보문고, 예스24, 리디, 밀리의 서재, 아마존 KDP (AI 저작 고지 정책 확인 항목 포함)

## 완료

`BOOK status`가 `완료`를 출력하는지 확인하고 알린다.

```
[4단계 모두 완료] 출판본 완성.
- output/{책}/final.docx (Word를 열 때 '필드 업데이트' 창이 뜨면 '예'를 눌러도 안전합니다. 차례의 쪽 번호가 채워집니다)
- output/{책}/metadata.md
- output/{책}/verify-report.md, build-report.md
```

Claude 앱과 ChatGPT에서는 결과물을 내려받기 폴더로 복사해 링크를 드리고, 마지막 작업 묶음 ZIP도 함께 내려받게 한다.
